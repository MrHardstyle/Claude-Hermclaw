# 20261008-006 – LiteLLM Proxy als Model Gateway

## Question
Wie werden die Modellrollen über LiteLLM (auf `.225:4000`) an Ollama (`.224:11434`) angebunden, inkl. strukturierter Ausgabe und Health?

## Why needed
P08 Model Gateway.

## Sources
- LiteLLM Ollama Provider: https://docs.litellm.ai/docs/providers/ollama
- LiteLLM Proxy Health: https://docs.litellm.ai/docs/proxy/health
- LiteLLM Proxy Config: https://docs.litellm.ai/docs/proxy/configs
- pydantic-ai Ollama (Hinweis zu response_format/json_schema ab Ollama 0.5): https://pydantic.dev/docs/ai/api/models/ollama/index.md

## Source date/version
Abruf 2026-10-08; Verifikation gegen installiertes LiteLLM in P08 (Testprotokoll in TEST_MATRIX.md).

## Relevant facts
- `model_list[].litellm_params.model: ollama_chat/<tag>` routet auf Ollama `/api/chat`; `api_base`, `keep_alive`, `num_ctx` als Parameter.
- Health: `/health/liveliness` (unauthentifiziert), `/health/readiness`, `/health` prüft alle Modelle.
- OpenAI-kompatibler Endpoint `/v1/chat/completions`, `/v1/embeddings`.
- Ob `response_format: {type: json_schema}` bei `ollama_chat` auf Ollamas `format` gemappt wird, ist in den Docs nicht eindeutig belegt → empirischer Test gegen das installierte LiteLLM (P08).

## Compatibility with our hardware
LiteLLM läuft auf `.225` (CPU), keine GPU nötig.

## Rejected alternatives
Direktaufrufe der Runtime an Ollama – Architektur verlangt LiteLLM als Abstraktion.

## Decision fixed by architecture
LiteLLM Gateway auf `.225`, Ollama auf `.224`.

## Implementation consequences
- Runtime-Gateway (`hermclaw.models.gateway`) spricht ausschließlich OpenAI-kompatibles HTTP gegen LiteLLM.
- Strukturierte Ausgabe: `response_format={"type":"json_schema","json_schema":{...}}`; zusätzlich wird das Ergebnis immer mit Pydantic validiert (Repair-Schleife max. 2).
- Load/Unload/Status (`/api/ps`, `keep_alive: 0`) laufen über den Model-Worker auf `.224` (direkt an Ollama), weil LiteLLM keine Residency-Steuerung bietet.
- Aliasse: `fast-router`, `planner-gemma`, `planner-gemma-fallback`, `coder-main`, `heavy-review`, `embedding`.

## Open risks
Mapping-Verhalten kann sich zwischen LiteLLM-Versionen ändern → Contract-Test im Repo.
