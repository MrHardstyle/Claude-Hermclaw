# 20261008-015 – GitLab (`.226`): Branches, Protected Branches, Merge Requests

## Sources
- Protected branches API: https://docs.gitlab.com/api/protected_branches
- Protected branches (User-Doku): https://docs.gitlab.com/user/project/repository/branches/protected/
- Merge requests API: https://docs.gitlab.com/api/merge_requests/
- Ansible gitlab_merge_request: https://docs.ansible.com/projects/ansible/latest/collections/community/general/gitlab_merge_request_module.html

## Relevant facts
- `POST /projects/:id/merge_requests` mit `source_branch`, `target_branch`, `title` (Pflicht), `description`.
- `GET /projects/:id/protected_branches` liefert Schutzregeln; Rückgabe-ID eines MR ist global, `iid` ist projektbezogen.
- Duplikate vermeiden: vorher `GET /projects/:id/merge_requests?source_branch=…&state=opened`.
- Authentifizierung mit `PRIVATE-TOKEN` Header (Project/Group Access Token).

## Decision fixed by architecture
GitLab `.226` ist Git-Remote; `main` geschützt; LLM pusht nie.

## Implementation consequences
- Git-Transport über SSH (dedizierter Deploy-Key mit Schreibrecht nur auf `hermclaw/*`-Branches – per Protected-Branch-Regeln auf GitLab-Seite).
- `GitLabClient` (httpx) für MR-Erstellung (optional) und Abfrage geschützter Branches; Runtime verweigert Push auf geschützte Branches zusätzlich lokal.
